# AI agent development

How this repository configures Codex and Claude Code, and how to keep the two
configurations from drifting apart.

## Supported agents

| Agent | Instructions | Skills |
| --- | --- | --- |
| Codex | `AGENTS.md` | `.agents/skills/` (read directly) |
| Claude Code | `CLAUDE.md` | `.claude/skills/` (generated mirror) |

## Canonical sources

Two files own the shared content. Everything else derives from them.

- **`AGENTS.md`** owns the repository-wide working agreements.
  `CLAUDE.md` starts with an `@AGENTS.md` import, so Claude Code loads the same
  rules and then appends its own short section. Nothing is duplicated.
- **`.agents/skills/<name>/SKILL.md`** owns each skill.
  `.claude/skills/` is generated from it.

Codex scans `.agents/skills` from the working directory up to the repository root.
Claude Code loads project skills only from `.claude/skills`, which is why the mirror
exists. A symlink would remove the duplication, but creating one on Windows needs
Administrator rights or Developer Mode, so this repository uses a generated copy
instead.

Every generated file carries this banner directly under its frontmatter:

```html
<!-- Generated from .agents/skills/<name>/SKILL.md. Do not edit this file directly. ... -->
```

**Never edit anything under `.claude/skills/`.** Changes there are overwritten on
the next sync and fail CI in the meantime.

## Invoking a skill explicitly

- **Claude Code**: `/dotnet-testing`. The command name comes from the directory
  name. `/skills` lists what is loaded.
- **Codex CLI and IDE extension**: run `/skills`, or type `$` to mention a skill.
- **ChatGPT**: type `@` to select a skill.

Skills also load automatically when the task matches their `description`, which is
why each description states both what the skill covers and when it must not fire.

## Validating

```bash
python3 scripts/validate-agent-skills.py
```

On Windows use `python` if `python3` is not on the path. The script uses the
standard library only and changes nothing without `--sync`.

It checks that each skill has a `SKILL.md` with valid frontmatter, that `name` is
present, lowercase kebab-case, shorter than 64 characters and equal to the directory
name, that `description` is present and long enough to drive triggering, that only
Agent Skills specification fields are used, that no placeholder text or absolute
local path leaked in, that referenced `references/` files exist, that no readme,
changelog or empty optional directory is present, that `CLAUDE.md` imports
`AGENTS.md`, and that the `.claude/skills/` mirror matches the canonical tree
exactly.

## Updating shared content

1. Edit the canonical file under `.agents/skills/<name>/SKILL.md`.
2. Regenerate the mirror:

   ```bash
   python3 scripts/validate-agent-skills.py --sync
   ```

3. Commit both trees together.

The sync is idempotent, writes only below `.claude/skills/`, and deletes mirror
files whose canonical source is gone.

## Adding a skill

1. Create `.agents/skills/<kebab-case-name>/SKILL.md`.
2. Give it frontmatter with `name` (matching the directory) and `description`. Put
   every trigger word in the `description`, including when the skill must **not**
   fire, so unrelated tasks do not load it.
3. Write the body as imperative steps: when to use it, what to inspect first, the
   workflow, the checks, the antipatterns, how to verify.
4. Keep `SKILL.md` under roughly 250 lines. Move long tables and source links into
   `references/` inside the skill directory.
5. Do not add a readme, changelog or empty `scripts/`, `references/` or `assets/`
   directory.
6. Run the sync, then add the skill to the tables in `AGENTS.md`, `CLAUDE.md` and
   this document.

## Preventing divergence

- `AGENTS.md` is imported by `CLAUDE.md`, so the shared rules cannot fork.
- The validator fails when the skill trees differ, and CI runs it on every push and
  pull request to `develop` and `master` as part of the **Build and test** job.
- CI never writes files; a stale mirror is reported as a failure with the exact
  paths, and the fix is to run the sync locally and commit the result.
